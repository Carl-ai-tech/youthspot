# YouthScope 青年放大鏡｜團隊介紹與分工

依 Ray 本次提供的討論與說明整理。本文描述成員責任與上台分段，並不代表所有部署、AI 串接或驗證工作均已完成。團員顯示名稱使用 **Ray** 與 **Webb**。

## 可直接放進簡報的團員介紹

### Ray｜需求洞察與應用整合

從與青年局長官的交流出發，整理政策端面對的問題與實際需求，將痛點轉化為 YouthScope 的提案構思與應用情境。主責專案規劃、系統架構與人員分工，並負責應用整合、AWS 部署與 Amazon Bedrock AI 串接。

**上台重點：為什麼做、為誰做、如何落地。**

### Webb｜資料工程與技術實作

負責公開統計資料的蒐集、整理與年齡口徑對齊，實作資料分析、趨勢預測與技術驗證，建立可追溯來源及呈現不確定性的資料基礎。主講數據發現、模型方法、技術成果與適用限制。

**上台重點：資料如何處理、預測如何產生、結果能相信到什麼程度。**

## 工作責任與交接

| 工作 | 主責 | 對方提供的支援／交接 |
|---|---|---|
| 青年局痛點訪談、需求定義、提案構思 | Ray | Webb 核對資料能否支撐問題 |
| 使用情境、服務流程與專案協調 | Ray | Webb 提供可用能力、限制與技術工期 |
| 整體架構、應用整合、AWS 部署、Bedrock 串接 | Ray | Webb 提供可調用程式、輸入輸出契約及測試案例 |
| 政府資料蒐集、清理、年齡對齊、來源履歷 | Webb | Ray 明確定義畫面與使用者需要的口徑 |
| 統計分析、預測模型、回測與技術驗證 | Webb | Ray 將結果及限制轉成易懂的介面與說法 |
| 簡報技術內容與數據示範 | Webb | Ray 補上需求背景、價值、架構與落地段落 |
| 現場展示與答問 | 共同 | Ray 接需求／應用／架構／部署；Webb 接資料／方法／預測／誤差 |

部署交接需包含可重跑資料版本、API 契約、必要環境變數名稱（不含值）、模型呼叫規格與失敗模式。Bedrock 串接由 Ray 負責，資料與模型邏輯由 Webb 說明；避免兩人都只介紹工具，漏掉真實問題與證據。

## Ray 開場參考稿

> 這個專案的起點，是我們和青年局長官的一場討論。青年局面對的不只是資料散在不同地方，而是當有人提出一個青年問題時，要怎麼知道它是否存在、有多嚴重，以及能不能提早看到變化。
>
> 所以我們做了 YouthScope——青年放大鏡。把公開資料放在可以比較的尺度上，讓承辦看清楚趨勢、追到來源，再討論下一步。我負責整理需求、提案構思與應用落地；Webb 負責資料與技術實作。接下來請 Webb 示範：這些數字怎麼來、預測怎麼做，以及哪些地方仍需要保留判斷。

## 架構段落的銜接
