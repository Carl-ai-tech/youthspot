# YouthScope 工具說明

> 給青年局承辦與局長：有人提出「青年怎麼樣」的主張時，用官方資料回答**真的嗎、多嚴重、是不是我們的權責、能做什麼**；並在青年搬進搬出發生之前，先看到哪些行政區需要準備。

這個工具做兩件別的 AI 做不到的事：**把不存在的「青年」統計口徑製造出來**（各機關的年齡分組沒有一個切在 18–35 歲），以及**讓每一個數字都能被稽核**（來源、原始分組、推估方法、信心度；AI 寫的數字逐一比對回來源）。預測是在這兩件事之上長出來的。

## 一、解決什麼問題

| 局方的話（9/12 交流） | 問題 | 工具做什麼 |
|---|---|---|
| 「青年局是一個主題，不是專業局處，指標不明確。」命題原文：「因青年定義未有法規規範，故未特別針對青年族群進行調查分析。」 | 沒有任何機關以「青年」為單位做統計；青年資料都是別人統計別的東西時順便切出來的，年齡分組還不一樣 | **對齊引擎**：戶政單一年齡、主計五歲組、薪資「未滿25／25–29／30–39」切齊成《青年基本法》18–35 歲，每筆標推估方法與信心度，門檻來自回測 |
| 「你找的這些數據，跟你提出的『青年生存』是不是一定有關聯？」 | 每個指標要能回答它代理青年的什麼處境、為什麼選它、限制是什麼 | **資料履歷**：12 個官方資料集，每個數字點開看來源機關、期別、原始分組、方法、權重、信心度、為什麼看這個指標 |
| 「青年局要怎麼證明這是真的有需求存在還是沒有？存在的話有多嚴重？」 | 新設局處沒有自己的口徑，面對「你該負責青年結婚生子」「你來降失業率」無法接招也無法擋掉 | **議題答辯**：主張 → 真的嗎（數字＋來源）→ 多嚴重（六都、全國、五年前三把尺）→ 是不是青年局權責（公共參與、職涯發展、創業之內，還是該轉哪個局處）→ 能做什麼（規則推出、附證據） |
| 「這些事情在實際發生之前，我們根本不知道。有沒有辦法做預測？」 | 青年往租金低、通勤可接受的區聚集（新莊、林口、汐止），事後才知道，來不及準備 | **趨勢預警**：世代淨遷徙（扣掉少子化的真實搬進搬出）、每區八年序列、線性外推＋t 檢定＋區間、訊號、移入區準備／流出區挽留兩類政策選項 |

## 二、為什麼需要它——一個真實例子

「淡水的青年在流失嗎？」拿人口數看：18–35 歲比去年少 275 人。拿世代追蹤看（今年 25 歲的人一年前是 24 歲的同一批人，兩期相減）：**淡水一年淨移入 1,069 個青年，是全新北最多的區**。新北全市人口差 −21,755，世代淨遷入 +546——那兩萬人幾乎全是少子化，跟青年搬不搬走無關。

同一份官方資料、兩種算法、相反的結論。青年局若照人口差配資源，會把錢從最需要準備托育和交通的區抽走。

## 三、為什麼不直接用 ChatGPT／其他 AI

| 直接問通用 AI | 這個工具 |
|---|---|
| 沒有對齊過的資料——問「新北 18–35 歲勞參率」，它拿 15–24／25–44 硬湊，或給一個看起來合理的數字 | 對齊引擎先算出 18–35 歲（四種公式、回測門檻），AI 拿到的是已對齊、標信心度的數字 |
| 它會算數，算錯沒人知道；引用的「來源」可能不存在 | **AI 只做看懂，不做計算**。每個寫出的數字比對回來源記錄，對不上的標橘底；引用 [N] 點開就是那筆記錄的履歷 |
| 沒有「權責」概念——會直接建議青年局做生育補貼 | 權責對照：職涯／創業／公共參與是青年局的；居住、婚育、失業率主責在其他局處，答案寫「轉請 X 局、青年局可協作」 |
| 沒有嚴重度的尺 | 六都排名、全國對照、48 年時間序列都在頁面裡 |
| 預測是編的 | 預測是統計程式算的（線性外推、t 檢定、95% 區間、回測），AI 只解讀；不顯著就寫「方向不明」，全部標 experimental |
| 資料是訓練時的舊快照 | pipeline 每個來源有最後抓取時間與更新週期，過期就標；一鍵重抓 |
| 黑箱 | 每個數字、每條建議、每個預測都有依據頁——公部門把合規、可稽核排在效率前面 |

## 四、怎麼使用

**主畫面只有一件事：青年往哪裡搬、下一個是哪裡、青年局要先做什麼。**
左邊地圖預設「青年淨遷入率」，右邊「青年移入預警」列三組：正在移入（訊號＋明年預估）、下一個候選（條件像淡水但還沒起來）、持續流出；每一列按「問 AI」就把問題填進下面的問答框。往下是「下一個淡水」主區塊：各區走勢圖 → 條件最像的區 → 移入跟條件不符的區；想看模型怎麼算，展開「模型怎麼算的」。其餘資料（掃描、建議、洞察、權益、人口、就業、薪資、供需、六都、動態）全部收在「深入看 · 背景資料」，最後是「公式工具庫」（每條算法一句白話）與資料 pipeline。


### 情境 A：有人丟一個主張過來（答辯）
1. 右上角選城市（預設新北市）。
2. 把主張打進問答框：「青年局應該協助年輕人結婚生小孩」「新北青年失業很嚴重」「年輕人都搬去桃園了」。
3. 讀四段答案：真的嗎 → 多嚴重 → 是不是青年局權責 → 能做什麼。[N] 點開看來源；橘底數字是模型自己估的，參考為主。
4. 「匯出報告」→ PDF（含封面、資料版本、每個數字的履歷）；或「下載 CSV」。

### 情境 B：還不知道要問什麼（找議題）
1. 地圖切「青年淨遷入率」：綠＝搬進來、紅＝搬出去。切「工作機會密度」「所得中位數」看驅動因子。
2. 看施政建議與異常洞察：規則推出的建議附依據與信心度；通過統計檢定的變化附方法與點數。點「看圖」跳到證據。
3. 點「帶到問答」，把卡片變成問題交給模型在證據上推理。

### 情境 C：預測與準備
1. 問趨勢：「哪些區的青年正在移入？會持續嗎？」「推測臺南哪區流失會越來越嚴重」「林口的移入會不會減速」。
2. 看「青年動態」圖：移入前四區、流出前三區的八年序列；圖說有每區訊號、2027 預估與區間、信心度。2022–2023 是戶籍事件年。
3. 看兩條準備建議：移入區（托育、租補、交通、據點）／流出區（在地工作機會、返鄉方案、巡迴服務）。

### 其他入口
- **掃描檔／CSV／貼表格**：任何機關的統計表丟進來，年齡分組自動辨識，文字標籤才交模型判讀並標「推定」，三道查核後對齊。
- **六都比較**：「臺中和臺南失業率比較」「六都房價所得比」直接畫官方值。
- **資料缺口**：模型說「建議補蒐集 X」時，系統對照目錄回答 X 是官方沒有（查過哪些表）、已在儀表板、還是有但未接入。權益覆蓋盤點青年基本法第 7–23 條共 17 個面向。

## 五、「預測模型」是什麼——誠實的定義

不是機器學習。每區只有 8 個年度點，訓練出來的模型不可信也無法解釋；對公部門，**一個會被民代打臉的黑箱預測是負債**。模型分兩層，都是可解釋的統計：

### 第一層：每區的時間趨勢（已完成）
```
資料   世代淨遷入率(區, 年) = Σ_{a=18..35}[P(a,年) − P(a−1,年−1)] ÷ 一年前同世代人口，2019–2026
方法   最小平方線性外推；斜率雙尾 5% t 檢定；95% 預測區間（forecast.py，跟職缺預測同一套）
訊號   連續正值＝持續移入｜斜率顯著下降＝移入減速｜連續負值＝持續流出｜斜率顯著改變方向＝轉向｜其餘＝方向不明
回測   用 2019–2024 預測 2025、2019–2025 預測 2026，報每區 MAE 與「沿用去年值」基線
限制   戶籍≠實際居住；2022／2023 為疫情除籍與恢復戶籍的事件年；單年跳動（社宅入住）
```

### 第二層：為什麼移入——橫斷面驅動模型（已完成 `data/drivers.py`）
局長講的因果鏈：*收入低＋房價高 → 外移 → 流向租金低＋通勤可接受的區 → 聚集*。這是推拉理論（Lee 1966）＋空間均衡（Roback 1982：人在「工資 − 租金 ＋ 生活品質」之間移動到均衡）＋重力模型（規模、距離）。六都 158 區 pooled 迴歸，被解釋變數是三年平均淨遷入率：

| 推／拉因子 | 代理指標 | 158 區初步相關（2026-09-12） |
|---|---|---|
| 工作機會（拉） | 工作機會密度（普查從業員工 ÷ 15–64 歲人口） | r = +0.29；密度 ≥0.6 的 55 區平均 +0.33%，<0.3 的 42 區平均 −1.57% |
| 所得水準（拉） | 財政部各區綜合所得中位數 | r = +0.35 |
| 聚集效果（重力） | 18–35 歲人口規模（log） | r = +0.47 |
| 居住成本（推） | 實價登錄租賃案件各區每坪月租中位數（六都，已接） | 模型 B（109 區）：租金高 10% → −0.05 pp，不顯著；臺北固定效果 −2.5 pp（★）是房價的影子 |
| 通勤可及性 | 110 年普查工作地×居住地；捷運站數／通車年 | 待接 |
| 住宅供給（領先指標） | 建照／使照核發戶數——房子先蓋、人 1–2 年後才到 | 待接（data.gov.tw 只有縣市；區級在內政統計查詢網／SEGIS）。淡水殘差 +3.5 pp 就是它的證據 |

輸出是「哪些條件的區在吸青年」的係數，可**解釋**（淡水移入是租金低＋輕軌）與**提早指認**（哪些區的條件正在變得像淡水）。OLS、係數與標準誤全公開、標準函式庫可算。

**不能做的**：不宣稱因果；不用 158 個點跑複雜模型；不把兩層混成一個「預測分數」。

## 六、「趨勢分析 agent」——經濟學是解讀框架，不是計算工具

agent 的價值不是讓模型「想」，是讓模型按固定順序**呼叫我們的工具**，每步輸出可稽核。經濟學理論放在解讀模板裡。

```
「桃園龜山青年一直移入，青年局要注意什麼？」

程式步驟
 1. signals(區)      → 世代淨遷入率序列、訊號、預測與區間          [第一層]
 2. drivers(區)      → 工作機會密度／所得／規模／租金，對六都分位     [第二層輸入]
 3. benchmark(市)    → 六都與全國的尺
 4. policy_map(議題) → 權責表：青年局三件事之內，還是轉哪個局處
 5. rules(區)        → 規則推出的建議（移入區準備／流出區挽留）

模型只做第 6 步
 6. explain(1–5, 框架=推拉／空間均衡／重力)
    → 「龜山工作機會密度 1.03（六都前 20%）、所得中位數 55.7 萬、連續移入 +3.9%／年 —— 拉力型移入；
       準備順序：通勤、托育、租補申請量」
    → 每個數字帶 [N]，程式比對回工具輸出；對不上就標
    → 「可能原因（待驗證）」永遠標明，不寫「因為」
```

換模型（Bedrock 上任一）不影響正確性，因為數字不是它算的。

## 七、使用限制（上台要主動講）
- 戶籍資料量的是把戶籍遷來的青年；就學就業未遷籍的看不到。反過來說更接近「定居」。
- 行政區沒有失業率、薪資、行業（抽樣撐不到）；行政區用的是全面資料：戶政、稅籍、普查。
- 居住指標（房價所得比、貸款負擔率）是全體家戶；青年只會更重。
- 行業訊號是全國、全年齡——官方沒有行業 × 年齡（主計總處 67 張表逐一查過）。
- 預測是線性外推，八個點，區間寬；experimental 標籤到局方共同界定「提前多久、容許多少誤差」前都留著。
